# DigitalArch document workstation

## Direction

An exact, restrained archive workstation. Preserve the dark navy header, compact Ant Design controls, clear source/status labels and large document inspection area. This is an operational interface, not a marketing dashboard. No decorative imagery, gradients, oversized metric cards or new component library.

## Tokens and components

Ant Design **6.7.0**, icons **6.3.4**, `src/theme.js`, one global compact ConfigProvider. Working type is **13px**, small type **12px**, controls **28px**, system UI/Segoe UI, tabular numerals. Semantic statuses always include text, not color alone. Decorative action icons are hidden from accessible names; icon-only actions have explicit labels.

## Shell and navigation

The shell is viewport-contained (`100dvh`, `min-height:0`, `min-width:0`). The browser document never scrolls at supported desktop sizes; tables, thumbnails, preview viewports, drawers and modal bodies own scrolling. The header shows scanner status where permitted, the current user, password change and sign-out. Mode appears only in the scanner mode selector, not as repeated source text on thumbnails, preview headings or a header badge. Provenance stays in PostgreSQL. Footer shows active batch or **No active batch** and WIB timezone. During document review it instead shows included/reviewed pages, unresolved findings, cycle and revision. During OCR job inspection it shows processed/total pages, failures, scan-session count, the current processing page when available and a compact progress bar. Both workstations omit separate summary strips so the review area can grow. OCR footer state is job-scoped and cleared on leaving the job; it never starts or resumes processing. Storage implementation details stay in System/documentation.

Navigation derives from permissions. Operators open Capture Workspace, My Batches and Scanner. QC Officers open QC Queue; administrators have read-only QC oversight plus Users, Batch assignments, Audit Logs, Settings and System. Explicit combined roles expose their granted sets. Future-only users get a professional informational empty state, not dead navigation. Backend authorization is independent of the menu.

The right-hand status/account cluster is styled independently of the navbar: a compact scanner-status capsule, a small outlined user icon and bounded name, then a navy action group. Change password is a tooltip-labelled key icon; Sign out retains its icon and visible text. Controls use light focus outlines, quiet blue hover surfaces and explicit disabled states rather than white form-like buttons. Full names remain available on hover. Navbar height, background, brand, module label and workspace navigation are unchanged.

Staff have a bell directly in that top-navbar account group, with a personal unread badge. Its 600px bounded drawer owns its scrolling: Unread/All, Mark all read, individual read/unread and Newer/Older history. Opening details records a view and shows the full reason with document/QR action; Back returns to history even if reading removed the row from Unread. Closing is not reading. Status has text, not only row tint. Actor/date/batch context wraps. Existing capture/draft guards remain. This is an event-driven inbox, not recurring toast stacks; see [NOTIFICATIONS.md](NOTIFICATIONS.md).

Document details keep **QC Queue** selected for accounts with QC access, or **My Batches** for operator-only accounts. Common page actions (previous/next, rotation/reset, order, fit, reload and back) use the shared Ant Design icon buttons, with action names in hover/focus tooltips and accessible labels. QC decisions and bulk-review actions retain visible text and their existing confirmations.

## Authentication and administration

Sign-in and `/register` share a viewport-contained navy/white split: restrained product context at left and a clearly labelled form at right. Registration uses a compact two-column form, not a vertically scrolling document. Small-screen chrome contracts instead of introducing browser scrolling. Visible labels, password autocomplete, matching-password validation and pending/rejected confirmation states remain. A forced-password-change modal still blocks workspaces until successful. Errors remain actionable and do not expose account internals.

Users and Audit reuse the white `WorklistTable` surface, icon-bearing headings, internally scrolling rows and footer totals/pagination. Users has **All users** plus a count-bearing tab for each of the six roles, including empty roles; multi-role accounts appear under each assigned role. Counts ignore search/paging. Account identity groups the display name, username and a small **You** marker. Role tags wrap; access status includes text and a password-change reminder where relevant. Edit, enable/disable and reset are icon-only `IconButton` actions with accessible labels and hover/focus tooltips. **Create user** sits in the right-hand button cluster immediately beside Refresh; navbar structure and styling remain unchanged.

Create/edit/reset modals use 600px bounded forms, paired identity fields where space permits, grouped role access and a separated password section. Create and reset offer **Auto-generate** (default) or **Set password**, with 12–256-character validation and confirmation for manual passwords. Both modes issue temporary credentials shown once and cleared on dismissal; first-sign-in password change remains mandatory. Form/API errors stay inside the modal. Destructive account actions retain confirmation; current/last administrator protections and session revocation remain server-enforced.

Users also supports icon-only **Delete user**, with confirmation explaining retained ownership/history and reserved usernames. Deletion removes the account from the list, revokes sessions and prevents sign-in, without deleting its records. Checkboxes select up to 100 other accounts across pages; the toolbar shows the selected count and icon-only **Reset selected passwords**, **Delete selected users** and **Clear selection**. Filters/role changes clear selection. Bulk reset can set one shared temporary password or generate a different random password for each account; the credentials modal lists all results once. Shared credentials are for onboarding only, never a bypass of mandatory password change. Bulk operations are version-checked and transactional: no partial deletion/reset if any target is stale, missing or protected. No archive-batch deletion privilege is added.

Audit has **All events** plus count-bearing event-category tabs, search by event/actor/record and server-side paging over the complete filtered result. Tab counts remain independent of search/paging. Rows group readable event names with exact event codes, record types with IDs, and a short metadata preview. An icon-only **View event details** opens a read-only modal with complete metadata, event/record/batch/correlation IDs, actor and WIB timestamp. Role/category, search, sorting (Users) and paging restore from the URL; credentials and modal drafts never enter it. These changes have static verification only, not rendered/browser verification.

Existing scanner/document panes keep their current common components.

**Returned from QC** is a URL-backed view for `documents.workflow_status='rework'`, not a new capture status. Operators see assignments; returned work is excluded from ordinary In Progress/Paused. Sortable **Returned at** uses QC decision time, newest first; **(?)** exposes the reason. **Continue rework** and its notification action open preparation by default, with **Capture / rework** reserved for scan work. Saving metadata/Batch Info enables Resubmit without another completion/OCR when retained images are unchanged; ordering, labels and exclusions do not force recognition. New/changed images retain capture guards. A separate compact warning badge beside the document status (including **Returned from QC**), not beside Resubmit, explains a disabled Send/Resubmit action. The capture and document/QC toolbars share **Batch Info**, a 360px physical-location drawer. Operators can edit before submission/in rework; QC needs the live claim. Others can inspect read-only. Drawer values and batch version are captured on opening, errors remain inside it, and dirty location edits participate in navigation warnings. Review notes and OCR exception are disabled, not merely read-only, outside the live QC claim. Return confirmation explains reopening before handoff. The document footer replaces the plain summary with compact colored, icon-bearing Ant Design tags for included pages (blue), reviewed pages (green), unresolved findings (orange when nonzero, green at zero), cycle (geekblue) and revision (cyan). The table body fills its available panel height so horizontal scrolling stays below the body rather than immediately below a short list of rows.

Cancelled sessions are recorded as **interrupted** with a clear cancellation reason and the usual partial/interrupted acknowledgement before Complete Capture. No new modal confirmation or page deletion is introduced.

It must not claim cancellation finished or enable another scan; an administrator must verify the Windows helper/device is stopped before restarting the backend. ## Security and verification

Production HTML receives a per-response CSP style nonce. ConfigProvider forwards it to Ant Design.
